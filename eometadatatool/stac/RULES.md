# Rules for writing STAC item templates

This document defines the conventions for the Python item-template files at
`eometadatatool/stac/{mission}/template/stac_{mission}.py`.

A template is a small async module whose job is to turn a metadata-mapping
dict into a STAC `Feature` JSON. Everything heavy (geometry normalization,
hashes, alternate URLs, the `enclosure` link, base extensions, expiry, EOPF
timestamps) is handled by the framework — your template should stay declarative.

---

## 1. File location and naming

| Rule | Value |
|------|-------|
| Path | `eometadatatool/stac/{mission}/template/stac_{mission}.py` |
| Count | Exactly one file in `template/` whose name starts with `stac` |
| Companion | A `collection-{mission}.json` must live in the same `template/` folder |
| Examples | One or more example item JSON files must live in `examples/` |

The mission folder name and the collection string passed to `STACItem` should
match each other (e.g. folder `sentinel-2-l2a/` → `collection='sentinel-2-l2a'`).

In order to work with implemented tests all of the above must be true, otherwise tests will fail and/or not run at all.

---

## 2. The `render` entrypoint

The template module **must** export exactly one public coroutine with this
signature:

```python
async def render(attr: dict[str, Any]) -> dict[str, Any]:
    ...
    item = STACItem(...)
    return await item.generate()
```

Rules:

- Always `async`. It is awaited by the extraction pipeline.
- Input `attr` is the dict produced by the mapping loader (CSV + XPath). Treat
  it as the only source of metadata.
- The last statement is always `return await item.generate()`.

---

## 3. Imports — canonical order

Order them stdlib → first-party utilities → framework. Inside each group,
alphabetical.

```python
from typing import Any
# optional stdlib used by helpers: re, itertools.product, math.isnan, dateutil.parser

from eometadatatool.dlc import get_odata_id
from eometadatatool.flags import is_extended_private_data, is_hidden, is_no_private
from eometadatatool.stac.framework.stac_asset import (
    JPEG2000Asset,
    ProductManifestAsset,
    ThumbnailAsset,
    XMLAsset,
)
from eometadatatool.stac.framework.stac_bands import S2_Bands, generate_bands
from eometadatatool.stac.framework.stac_extension import StacExtension
from eometadatatool.stac.framework.stac_item import STACItem
from eometadatatool.stac.framework.stac_link import STACLink, TraceabilityLink
```

What lives where (reuse, do not reinvent):

- [stac_item.py](framework/stac_item.py) — `STACItem` dataclass, `STACItem.from_mgrs()` helper.
- [stac_asset.py](framework/stac_asset.py) — `STACAsset` and the typed subclasses.
- [stac_extension.py](framework/stac_extension.py) — `StacExtension` enum (the only allowed extension identifiers).
- [stac_link.py](framework/stac_link.py) — generic `STACLink`, `TraceabilityLink`. The `enclosure` `ZipperLink` is auto-generated by the framework — never instantiate it.
- [stac_bands.py](framework/stac_bands.py) — pre-defined band collections (`S1_Pols`, `S2_Bands`, `S2_NS_Bands`, etc.) and `generate_bands(...)`.
- [utils.py](framework/utils.py) — small helpers (`ensure_iso_datetime`, `EMPTY_MAPPING`, ...).

## 4. OData lookup

Standard pattern:

```python
extended_private_data = is_extended_private_data()
odata = await get_odata_id(attr['filepath'], zipper=extended_private_data)
```

For datasets that do not have an OData record (e.g. CopDEM), pass
`odata=None` to `STACItem`. The framework will skip OData-derived properties
(`created`, `updated`, `published`, `eopf:origin_datetime`) and the auto
`product` asset.

---

## 5. Building the properties dict (`extra`)

Build a single `props` dict and pass it as `extra=props`. The framework merges
it on top of its own baseline (`auth:schemes`, `storage:schemes`, the OData
timestamps, `processing:software`, `expires`, ...), so do **not** set any of
those yourself.

### 5.1 Mandatory time fields

```python
props = {
    'datetime': attr['beginningDateTime'],
    'start_datetime': attr['beginningDateTime'],
    'end_datetime': attr['endingDateTime'],
}
```

`start_datetime` / `end_datetime` may be omitted if it makes sense considering the nature of products,
however the framework will default to setting them equal to `datetime`.
This was implement because SFEOS requires them to be present.

### 5.2 Recognized property prefixes

Add only the prefixes that genuinely apply to the product. Adding a key from a
prefix means you must also list its `StacExtension` (see §7) — except for
prefixes the framework adds for you (`auth:`, `storage:`, `processing:software`,
`processing:facility`).

| Prefix | Extension | Typical use | Additional info                                                                                       |
|--------|-----------|------------|-------------------------------------------------------------------------------------------------------|
| `platform`, `constellation`, `instruments` | _(core)_ | All EO missions | If product uses multiple satellites then `platform` and `constellation` should be ommited             |
| `processing:level`, `processing:datetime`, `processing:version` | `PROCESSING` | All processed products | -                                                                                                     |
| `product:type`, `product:timeliness`, `product:timeliness_category` | `PRODUCT` | All products | `product:timeliness` should be an an [ISO 8601 Duration](https://en.wikipedia.org/wiki/ISO_8601#Durations) |
| `sat:absolute_orbit`, `sat:relative_orbit`, `sat:orbit_state`, `sat:orbit_cycle`, `sat:platform_international_designator` | `SATELLITE` | Orbiting platforms | -                                                                                                     |
| `view:sun_azimuth`, `view:sun_elevation`, `view:azimuth`, `view:incidence_angle`, `view:off_nadir` | `VIEW` | Optical / SAR with viewing geometry | -                                                                                                     |
| `eo:cloud_cover`, `eo:snow_cover` | `EO` | Optical | -                                                                                                     |
| `sar:frequency_band`, `sar:center_frequency`, `sar:instrument_mode`, `sar:polarizations`, `sar:resolution_range`, `sar:resolution_azimuth`, `sar:beam_ids` | `SAR` | SAR | -                                                                                                     |
| `proj:code`, `proj:shape`, `proj:bbox`, `proj:transform` | `PROJECTION` | Gridded data | - |
| `raster:scale`, `raster:offset` | `RASTER` | Scaled rasters (asset-level usually) | Omit if `raster:scale = 1` and `raster:offset = 0` |
| `grid:code` | `GRID` | Tiled grids (MGRS, WRS, ...) | - |
| `eopf:datatake_id`, `eopf:datastrip_id`, `eopf:instrument_mode`, `eopf:origin_datetime` | `EOPF` | Copernicus EOPF metadata | - |
| `classification:classes` | `CLASSIFICATION` | Class maps (asset-level) | - |
| `cube:dimensions`, `cube:variables` | `DATACUBE` | Multi-dimensional NetCDF | - |

> Sentinel-2 grid codes are a special case: call
> `props.update(STACItem.from_mgrs(mgrs, extensions))` instead of setting
> `grid:code` and `proj:code` by hand. It also adds the right extensions to a
> mutable set.

More information about what is permitted in each property can be found on respecting STAC extension GitHub page, e.g. [product extension](https://github.com/stac-extensions/product).

### 5.3 Conditional keys

Use the walrus operator and `attr.get`:

```python
if processor_version := attr.get('processorVersion'):
    props['processing:version'] = processor_version
```

### 5.4 The `_private` block

Always gated on `is_no_private()` and `is_hidden()`:

```python
private_flag = is_no_private()
hidden_flag = is_hidden()
if private_flag is False:
    props['_private'] = {}
    props['_private']['product_size'] = attr['private:product_size']
    props['_private']['product_uuid'] = odata.id
    props['_private']['product_name'] = odata.name
    if hidden_flag:
        props['_private']['visible'] = False
    else:
        props['_private']['visible'] = True

    if extended_private_data:
        props['_private']['brands'] = odata.zipper_data
```

For datasets without OData, derive `product_uuid` deterministically with
`generate_product_uuid(attr['identifier'])` or
`generate_product_uuid(attr['filename'])` (from
`eometadatatool.stac.framework.utils`) instead of `odata.id`, and set
`product_name` to the same value instead of `odata.name`. Use whichever key
the template uses as the item identifier, and keep it stable: changing it
changes the UUID of every existing product. Omit the
`if extended_private_data:` block entirely:

```python
if private_flag is False:
    props['_private'] = {}
    props['_private']['product_size'] = attr['private:product_size']
    props['_private']['product_uuid'] = generate_product_uuid(attr['identifier'])
    props['_private']['product_name'] = attr['identifier']
    ...
```

## 6. Assets

### 6.1 Container

Always a `dict[str, STACAsset]`, keyed by short snake-case asset names:

```python
assets: dict[str, STACAsset] = {
    'safe_manifest': ProductManifestAsset(...),
    'product_metadata': XMLAsset(...),
}
```

### 6.2 Pick the right subclass

Use the most specific subclass — it sets `media_type` and sensible default
`roles` for you. Fall back to `STACAsset` only when none fits.

| Subclass | Media type | Default roles | When |
|----------|-----------|---------------|------|
| `ProductManifestAsset` | `application/xml` | `('metadata',)` | SAFE / XFDU manifests |
| `XMLAsset` | `application/xml` | _(set explicitly)_ | Other XML metadata |
| `NetCDFAsset` | `application/netcdf` | `('data',)` | NetCDF data |
| `CloudOptimizedGeoTIFFAsset` | `image/tiff; ...; profile=cloud-optimized` | `('data',)` | COGs — auto-fills `proj:*`, `data_type`, `nodata` from the file via gdalinfo |
| `GeoTIFFAsset` | `image/tiff; application=geotiff` | `('data',)` | Plain GeoTIFFs |
| `JPEG2000Asset` | `image/jp2` | `('data',)` | JP2 |
| `HDFAsset` | `application/x-hdf` | `('data',)` | HDF |
| `ThumbnailAsset` | _(auto-detected from path)_ | `('thumbnail',)` | Quicklooks; `is_https_public=True` is forced |
| `ProductAsset` | `application/zip` | `('data', 'metadata', 'archive')` | **Do not instantiate** — `STACItem.product_asset_name` triggers it automatically |

### 6.3 Required arguments

For every `STACAsset` (and subclasses):

- `path` — full filesystem/S3 path. Strip trailing `/` is automatic.
- `title` — human-readable title. Subclasses with a fixed title omit this.
- `roles` — required when not defaulted.
- `checksum` and `size` — set them whenever the mapping has them. The framework
  drops `file:size` if zero and converts `checksum` to a multihash automatically.
- `checksum_fn_code=0x16` for SHA-256 (default is `0xD5` for MD5). Sentinel-2
  uses `0x16`.

### 6.4 Asset-level extension properties go in `extra`

```python
JPEG2000Asset(
    path=...,
    title=...,
    roles=('data', 'reflectance'),
    checksum=...,
    size=...,
    checksum_fn_code=0x16,
    extra={
        'bands': generate_bands(S2_Bands, ('B04',)),
        'data_type': 'uint16',
        'nodata': 0,
        'gsd': 10,
        'proj:code': 'EPSG:32633',
        'proj:shape': [10980, 10980],
        'raster:scale': 1.0 / 10000,
        'raster:offset': 0.0,
    },
)
```

The framework auto-adds the `EO` and `SAR` extensions when an asset's `bands`
contains `eo:` / `sar:` keys, and adds `FILE` when any `file:*` key appears.

**Prefer hardcoding over gdalinfo.** A `CloudOptimizedGeoTIFFAsset` spawns a
`gdalinfo` subprocess — roughly one second per asset against S3, and these run
one after another — unless `data_type`, `nodata`, a projection (`proj:code` /
`proj:wkt2` / `proj:projjson`) and two of `proj:bbox` / `proj:shape` /
`proj:transform` are *all* supplied in `extra`. Whenever these values are fixed
by the product spec, write them out; a scene with 17 COG assets otherwise pays
17 sequential remote reads to learn constants.

If a file genuinely has no nodata value, say so explicitly with `'nodata': None`.
That counts as known — so gdalinfo is skipped — and the key is dropped from the
output rather than emitted as `null`. Leaving `nodata` out entirely means
"unknown, go look it up", which is what triggers the subprocess.

### 6.5 Optional / conditional assets

```python
if (ql_path := attr.get('ql:path')) is not None:
    assets['thumbnail'] = ThumbnailAsset(
        path=ql_path,
        checksum=attr.get('ql:checksum'),
        size=attr.get('ql:size'),
    )
```

### 6.6 Loop patterns

Use `itertools.product` to expand combinatorial assets (e.g. SAR
beams × polarizations) and a per-band loop for multi-resolution rasters. Build
asset keys with f-strings: `f'{beam}-{pol}'`, `f'{band_id}_{res}m'`.

## 7. Extensions

`StacExtension` ([framework/stac_extension.py](framework/stac_extension.py)) is
the **only** allowed source of extension URIs — never hard-code a schema URL.

### 7.1 What the framework adds for you

Always present, do not list them again:

- `AUTHENTICATION`, `STORAGE`, `TIMESTAMP`, `PROCESSING`
- `EOPF` (when `eopf=True` and OData is present)
- `ALTERNATE` (when an asset has multiple alternates)
- `FILE` (when an asset has any `file:*` property)
- `EO`, `SAR` (when an asset declares `bands` with the matching prefix)

### 7.2 Two ways to declare extensions

**Static tuple** when the set is fixed at write time:

```python
extensions=(
    StacExtension.EO,
    StacExtension.RASTER,
    StacExtension.SATELLITE,
    StacExtension.GRID,
    StacExtension.VIEW,
    StacExtension.CLASSIFICATION,
    StacExtension.PRODUCT,
    StacExtension.PROJECTION,
)
```

**Mutable set** when the set depends on data (e.g. MGRS helper, optional
fields):

```python
extensions: set[StacExtension] = {
    StacExtension.PROJECTION,
    StacExtension.PRODUCT,
}
if 'eo:cloud_cover' in props:
    extensions.add(StacExtension.EO)

item = STACItem(..., extensions=extensions, ...)
```

### 7.3 Recommended baseline by family

| Family | Extensions on top of framework defaults |
|--------|------------------------------------------|
| Optical (S2, Landsat) | `EO`, `RASTER`, `SATELLITE`, `GRID`, `VIEW`, `CLASSIFICATION`, `PRODUCT`, `PROJECTION` |
| SAR (S1) | `SATELLITE`, `PRODUCT`, `PROJECTION`, `SAR`, `VIEW` |
| Atmospheric (S5P) | `PRODUCT`, `PROJECTION`, `SATELLITE`, `DATACUBE` (`+EO` for L1) |
| Altimetry (S3 SR, S6) | `SATELLITE`, `PRODUCT`, `ALTIMETRY`, `PROJECTION` |
| DEM (CopDEM) | `PROJECTION`, `ALTERNATE`, `GRID`, `SAR` |

## 8. Links

The `enclosure` link to the source directory is auto-generated by the
framework (`ZipperLink`). For products with traceability you can add a
`TraceabilityLink`:

```python
links: list[STACLink] = [
    TraceabilityLink(href=f'{odata.name}.zip'),
]
```

Custom links are plain `STACLink(...)` instances and require all four fields
(`rel`, `href`, `media_type`, `title`). `rel` must be one of the allowed
values from the `LinkRel` Literal in [stac_link.py](framework/stac_link.py).

## 9. `STACItem` construction

```python
item = STACItem(
    path=item_path,                   # filesystem / S3 path of the scene
    odata=odata,                      # ODataInfo or None
    collection='sentinel-2-l2a',      # matches the collection-*.json
    identifier=attr['identifier'],    # item id
    coordinates=attr['coordinates'],  # WKT polygon string
    links=links,                      # optional, default ()
    assets=assets,                    # required
    product_asset_name='Product',     # default 'product'; None to disable auto-asset
    extensions=(...),                 # iterable of StacExtension
    extra=props,                      # the properties dict
    eopf=True,                        # default True; relies on OData
)
return await item.generate()
```

Notes:

- `coordinates` is parsed as WKT and normalized — pass it untouched.
- Set `eopf=False` only for non-Copernicus / external datasets where the
  `eopf:origin_datetime` field would be wrong.
- Do not set `bbox`, `geometry`, `expires`, `auth:*`, `storage:*`,
  `processing:software`, the `enclosure` link, or the auto product asset
  yourself — the framework owns them.

## 10. Helper functions

When the same lookup repeats (timeliness code, mode → beam list, EPSG from a
zone string), extract a module-private function. Convention:

- Pure: takes simple arguments, returns simple values.
- Use `match/case` and end with `raise ValueError(f'Unsupported X {x!r}')`.

```python
def _get_timeliness(timeliness: str) -> str | None:
    match timeliness:
        case 'Fast-24h':
            return 'PT24H'
        case 'NRT-10m':
            return 'PT10M'
        case 'Reprocessing':
            return None
    raise ValueError(f'Unsupported timeliness {timeliness!r}')
```

## 11. Style rules

- **Python 3.14+** syntax: `X | None`, `match/case`, walrus `:=`, PEP 695
  type aliases. No `Optional`, no `Union`.
- **Type-annotate every public symbol.** Use `Collection[str]`, `Mapping[str, Any]`,
  `dict[str, Any]`, `tuple[...]` from collections.abc / builtins.
- **No defensive `try/except`** for missing mapping keys — let `KeyError`
  surface. The CSV mapping is the contract; if a key is missing it is a
  mapping bug, not a runtime concern.
- **No comments** unless you are explaining a non-obvious *why* (a workaround,
  a unit conversion that looks wrong, a product-specific solution). Section comments
  like `# AOT assets` are fine where they delimit large generated blocks.
- **No logging** in templates.
- **Reuse band catalogues.** Do not define bands locally; pull them from
  [stac_bands.py](framework/stac_bands.py), if necessary add new bands to that file.
- **Pass tuples, not lists**, for fixed-size enumerations (`roles`,
  `extensions`, `bands`). Use lists only for things that genuinely vary in
  length per product.

## 12. Skeleton

Drop this into `eometadatatool/stac/{mission}/template/stac_{mission}.py` and
fill in the `# TODO` markers.

```python
from typing import Any

from eometadatatool.dlc import get_odata_id
from eometadatatool.flags import is_extended_private_data, is_hidden, is_no_private
from eometadatatool.stac.framework.stac_asset import (
    ProductManifestAsset,
    STACAsset,
    ThumbnailAsset,
    XMLAsset,
)
from eometadatatool.stac.framework.stac_extension import StacExtension
from eometadatatool.stac.framework.stac_item import STACItem
from eometadatatool.stac.framework.stac_link import STACLink, TraceabilityLink


async def render(attr: dict[str, Any]) -> dict[str, Any]:
    item_path: str = attr['filepath']

    props: dict[str, Any] = {
        'datetime': attr['beginningDateTime'],
        'start_datetime': attr['beginningDateTime'],
        'end_datetime': attr['endingDateTime'],
        'platform': f'sentinel-{attr["platformSerialIdentifier"].lower()}',  # TODO
        'constellation': attr['platformShortName'].lower(),                  # TODO
        'instruments': [attr['instrumentShortName'].lower()],                # TODO
        'processing:level': 'L1',                                            # TODO
        'product:type': attr['productType'],                                 # TODO
    }

    extended_private_data = is_extended_private_data()
    odata = await get_odata_id(item_path, zipper=extended_private_data)

    private_flag = is_no_private()
    hidden_flag = is_hidden()
    if private_flag is False:
        props['_private'] = {}
        props['_private']['product_size'] = attr['private:product_size']
        props['_private']['product_uuid'] = odata.id
        props['_private']['product_name'] = odata.name
        if hidden_flag:
            props['_private']['visible'] = False
        else:
            props['_private']['visible'] = True

        if extended_private_data:
            props['_private']['brands'] = odata.zipper_data

    assets: dict[str, STACAsset] = {
        'safe_manifest': ProductManifestAsset(
            path=f'{item_path}/manifest.safe',
            title='manifest.safe',
            checksum=attr['manifest.safe:checksum:MD5'],
            size=attr['manifest.safe:size'],
        ),
        # TODO: add product-specific data assets here
    }

    if (ql_path := attr.get('ql:path')) is not None:
        assets['thumbnail'] = ThumbnailAsset(
            path=ql_path,
            checksum=attr.get('ql:checksum'),
            size=attr.get('ql:size'),
        )

    links: list[STACLink] = [
        TraceabilityLink(href=f'{odata.name}.zip'),
    ]

    item = STACItem(
        path=item_path,
        odata=odata,
        collection='mission-collection',  # TODO: must match collection-*.json
        identifier=attr['identifier'],
        coordinates=attr['coordinates'],
        links=links,
        product_asset_name='Product',
        assets=assets,
        extensions=(
            StacExtension.SATELLITE,
            StacExtension.PRODUCT,
            StacExtension.PROJECTION,
            # TODO: add extensions matching the prefixes used in props/assets
        ),
        extra=props,
    )

    return await item.generate()
```

- [sentinel-2-l2a/template/stac_s2l2a.py](sentinel-2-l2a/template/stac_s2l2a.py) — rich optical: many bands, multi-resolution loops, classification map, MGRS-via-attr, EOPF.

## 14. Pre-merge checklist

Before opening a PR for a new template, verify:

- [ ] File exists at `eometadatatool/stac/{mission}/template/stac_{mission}.py`.
- [ ] `render` is `async`, returns `await item.generate()`.
- [ ] Sibling `collection-{mission}.json` exists in the same `template/` folder and, ideally, is created using [collection-maker](https://gitlab.cloudferro.com/jchojnacki/collection-maker).
- [ ] Example products are added to test bucket.
- [ ] At least one example item lives in `examples/` and examples were generated from test bucket, not `eodata`.
- [ ] CLAS knows about the new product: entries added in
      `eometadatatool/clas/product_type.py`,
      `eometadatatool/clas/template.py`.
- [ ] `python .venv/bin/pytest -n auto` passes.
